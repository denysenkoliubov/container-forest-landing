Усі ваші сервери на одній галявині

Керуйте Docker-контейнерами на кількох серверах з однієї вебпанелі, з Discord або з терміналу. Конфігурація живе в git, а секрети в ньому зашифровані.

Для кого

Для кількох серверів і невеликої команди

Звичайний Docker і Compose, без Kubernetes і Swarm. Для команди, де в людей різний рівень доступу.

Усі сервери в одному місці

Стан кожного сервера й контейнера видно в панелі. Не треба заходити на кожен по SSH.

Секрети в git, але зашифровані

Конфігурація разом із паролями лежить в одному репозиторії. Відкритим текстом не зберігається нічого.

Рівно стільки доступу, скільки треба

Дайте людині право перезапускати один сервіс на одному сервері, без повного доступу до решти.

Перезапуск з телефона

Сервіс упав, а ноутбука поруч немає? Одна команда в Discord, з тими самими правами, що й у панелі.

Архітектура

Агент дзвонить сам

На кожному сервері працює агент. Він сам підключається до центрального сервісу і тримає з ним постійний gRPC-стрім.

Жодних відкритих портів

Docker API не виставляється в мережу. Сервери можуть стояти за NAT: з'єднання завжди починає агент.

Лише відомі команди

Агент виконує фіксований набір типізованих команд з Protocol Buffers. Команди «виконай довільний shell» немає.

Права живуть у центрі

Ролі й секрети знає лише центральний сервіс. Панель, бот і CLI просто ховають недоступні дії.

SOPS + age

Пароль у git, але прочитати його нікому

Секрети шифруються окремим ключем для кожного сервера. Розшифровуються вони лише в центральному сервісі, безпосередньо перед розгортанням. Editor у своєму клоні репозиторію бачить їх відкритим текстом завдяки git-фільтру forest.

Ролі

Доступ на сервер або на один стек

Роль видається на все середовище або на окремий стек. На стеку діє більша з двох ролей.

Дія Viewerдивиться Operatorперезапускає Editorрозгортає Adminкерує всім
Стеки, стан і логи✓✓✓✓
start / stop / restart–✓✓✓
exec і консоль (у планах)––✓✓
Редагування стеку й деплой––✓✓
Користувачі й журнал аудиту–––✓

Editor на середовищі фактично має root на хості: compose-файл може змонтувати / або запустити privileged-контейнер. Видавайте цю роль свідомо.

Дорожня карта

Що вже росте і що посаджено

Уже працює

у продакшні з жовтня
  • Агент на кожному сервері: реєстрація за одноразовим токеном, статус онлайн і офлайн
  • Контейнери, їхній стан і логи; запуск, зупинка, перезапуск
  • Деплой стеку з публічного чи приватного git-репозиторію: вручну, після push або з CI; історія деплоїв з прив'язкою до комітів
  • Секрети SOPS з окремим ключем для кожного сервера; у клоні репозиторію їх редагують відкритим текстом через forest
  • Окремі дії restart, redeploy, redeploy with pull і down
  • Ролі Viewer, Operator, Editor, Admin на сервер або на стек, журнал аудиту
  • Вхід за паролем, passkey або через Discord
  • Discord-бот з командами, меню й сповіщеннями: деплої, падіння контейнерів, агенти офлайн
  • CLI forest: вхід через браузер і API-токени з обмеженнями (лише читання, окремі сервери, строк дії)
  • Деплой лише комітів, підписаних SSH-ключем користувача або підтверджених у панелі
  • Панель українською й англійською, з оновленнями наживо, версткою для телефона і встановленням як застосунок
